# BP-001: Monorepo Authentication Foundation

## Objective

Create the base monorepo for the RFP document filling tool with FastAPI backend, Next.js frontend, Supabase-backed auth/database services, Docker Compose orchestration, and OpenAPI-generated frontend client workflow.

## Implementation Steps

1. Create root Docker Compose orchestration for backend, frontend, Postgres, Auth, PostgREST, and Kong.
2. Create root `justfile` commands for stack lifecycle, logs, backend tests, and OpenAPI generation.
3. Move backend into `apps/backend` with FastAPI app structure, `pydantic-settings`, SQLModel model scaffold, health route, and authenticated `/api/v1/me` route.
4. Create frontend in `apps/frontend` with Next.js home page, Supabase browser client, login/sign-up flow, and starter document workspace.
5. Add OpenAPI Generator workflow and generated TypeScript client under `apps/frontend/src/lib/api/generated`.
6. Add local Supabase bootstrap SQL and Kong routing config.
7. Add root and app-level `.gitignore` files.
8. Verify backend tests, frontend production build, Docker Compose stack, backend health, Supabase Auth health, and frontend HTTP response.

## Architectural Decisions

- Use a monorepo with `apps/backend` and `apps/frontend`.
- Use FastAPI OpenAPI output as the source for generated frontend API client code.
- Use Dockerized OpenAPI Generator to avoid host Java dependency.
- Use Supabase Auth directly from the frontend and validate bearer JWTs in the backend.
- Use local Docker Compose Supabase services rather than requiring the Supabase CLI for the initial local stack.
